# 复现步骤

从本地客户端到成品 HTML 的完整流程。所有路径按你自己的机器改。

## 0. 前置

| 依赖 | 版本 |
|---|---|
| .NET SDK | 10.x（`dotnet` 需在 PATH，或用 `C:\Program Files\dotnet\dotnet.exe`） |
| Python | 3.10+（需 numpy） |
| Node.js | 18+ |
| 轻量包 | `nrc-lightweight-kit`，提供 PAK 挂载方式、32 字节 base key、`CUE4Parse-Natives.dll` |

从轻量包里取两样东西：

- `secrets/base-key.bin` —— 32 字节 PAK 解密密钥；
- `character/native/CUE4Parse-Natives.dll` —— ACL 原生解码库。**放到仓库的 `native/` 目录**（已 gitignore）。

> `native/CUE4Parse-Natives.dll` 不入库：它是轻量包的一部分，不适合随仓库分发。
> 仓库里的 `NrcChar.csproj` 会同时尝试 `native/` 和原始工作区布局，找不到就跳过拷贝（构建不会失败，但运行时会缺 DLL）。

## 1. 提取角色

```powershell
dotnet run --project tools/NrcChar -c Release -- `
  --paks "<游戏>\Win64\NRC\Content\Paks" `
  --out  "work\npc06201" `
  --key  "<kit>\secrets\base-key.bin" `
  --npc  NPC_06201 `
  --textures "T1,T2,T3" `
  --clips   "ClipA,ClipB" `
  model textures anim poses dialogue
```

**位置参数是命令**，按需要组合：

| 命令 | 作用 |
|---|---|
| `model` | 网格、蒙皮、骨骼、材质段、顶点色、双 UV |
| `textures` | 贴图解码（含 mip 与平台去扭转） |
| `anim` | 原版动作（ACL 解码） |
| `poses` | 附加骨骼姿势（PoseAsset） |
| `dialogue` | 对话 / 面部曲线（`TestData_*.uasset`） |

**可选参数**：`--mesh`（默认 `SKM_<NPC>_Skin`）、`--root`（默认 `/Human/NPC/<NPC>/`）、`--filter` / `--exclude`（按路径过滤扫描）。

**两个硬性要求**：

1. `--textures` 和 `--clips` 里写下的名字必须是**真实存在**的资源名。写错一个名字，`prepare_multi.py` 会直接抛 `Missing texture` 中断整条流水线。
2. `--out` 必须在 PAK 目录**之外**（代码里会强制校验）。

挂载成本：381 个 pak、1,010,590 个文件，一次完整挂载约 **4–6 分钟**。把多个命令合并在一次运行里，别反复挂载。

正常输出会带一行：

```
MOUNT files=1010590; block fixes=<n>
```

`block fixes` 是针对该游戏 PAK 压缩块布局的已知修正（`FPakEntry.CompressionBlocks` 的实际布局与通用解析器假设不同）。这一步是**确认过的格式修正，不是猜测**——解析器对块数、块大小与压缩策略都有边界检查，不符合就抛错而不是瞎解。

## 2. 动画准备与校验

有 PoseAsset 的角色：

```powershell
python tools/charextract/prepare_anim.py --data work\npc06201
```

**没有 PoseAsset**（`PA_*` 是 PhysicsAsset）的角色用专用脚本，它会解出原版曲线并写出**空的** `poses.json`，同时在 manifest 里注明来源：

```powershell
python tools/charextract/prepare_anim_noposeasset.py --data work\npc06201
```

然后校验蒙皮：

```powershell
python work\npc06201\animation-research\native-animation\validate_animation_exports.py
```

期望 `passed = true`。参考蒙皮误差应在 1e-5 cm 量级；四元数范数误差应在 1e-7 量级；权重和必须是 `[1.0, 1.0000001]`。

## 3. 装配

```powershell
python tools/charextract/prepare_multi.py `
  --data      work `
  --materials materials `
  --shaders   materials\shaders `
  --manifest  manifest\characters.manifest.json `
  --out       work\preview
```

`materials` 目录放每个材质的解析结果（`MI_*.json`），`materials\shaders` 放各 BasePass 程序的 `*-evaluated.json` 常量缓冲。

输出示例：

```
PREPARED npc00401     kernel=npc  vertexs=13643   textures=14  anim=True
PREPARED npc01101     kernel=npc  vertexs=8522    textures=14  anim=True
PREPARED npc06201     kernel=npc  vertexs=11722   textures=17  anim=True
PREPARED 3 characters
```

## 4. 导出变形目标与口型曲线

```powershell
python tools/charextract/prepare_morph.py `
  --data  work `
  --chars work `
  --out   work\preview\preview\assets
```

这一步把两半数据接起来：

- `chars\<角色>\animation-research\morph-poses\morph-deltas.bin` —— `UMorphTarget` 的 LOD0 顶点增量；
- `chars\<角色>\animation-research\native-animation\<clip>-native.json` —— 每个 clip 的浮点曲线（`CompressedCurveNames` 与 `CompressedCurveData.FloatCurves` 按索引对齐）。

脚本**按名字配对**（曲线名 == 变形目标名），只保留能配上的曲线；其余工具通道（`EC_Eye`、`Move_Velocity`、缩放类曲线等）统计后丢弃。`ec_u/v_offset_*` 是例外——它属于眼睛注视数据，由下一节的 `prepare_eye_gaze.py` 单独导出进包。插值以 `RCIM_Cubic` 为主，前端按 Hermite 切线求值。

输出：

```
work\preview\preview\assets\<角色>\morph\
├── targets.json   变形目标顺序（索引即 blend shape 序号）与顶点计数
├── deltas.bin     morph-deltas.bin 原样拷贝
└── curves.json    {clips: {clipName: {curveName: {interp, keys:[[t,v,a,l]]}}}}
```

**顺序要求：必须排在 `prepare_multi.py` 之后**——`prepare_multi.py` 会 `shutil.rmtree` 重建 `<out>/assets/<角色>/animation/`。

没有变形目标的角色（如 `NPC_00401`）会打印 `SKIP <角色> no morph-poses` 并跳过，**不算错误**。

### 4.1 导出原版眼睛注视曲线

```powershell
python tools/charextract/prepare_eye_gaze.py `
  --data  work `
  --chars work `
  --out   work\preview\preview\assets
```

从 `chars\<角色>\animation-research\native-animation\<clip>-native.json` 里只取 4 条
`ec_u_offset_l/r`、`ec_v_offset_l/r`，**原值导出**（不做符号翻转、钳制、归一化或缩放），输出到
`<角色>/gaze/curves.json`。`pack_multi.py` 遍历 `preview/` 下所有 `.json`，会自动把新文件内联。

实测：`NPC_01101` 11 个 clip、`NPC_06201` 94 个 clip 带注视曲线；`NPC_00401` 是旧提取布局，
没有 `animation-research/native-animation/`，脚本打印 `SKIP` 并跳过——前端 `loadGaze()` 返回 `null`，
预览里的「原版注视曲线」开关会提示无数据并回退为 0，**不算错误**。

### 4.2 导出原版面部 controllerConfig（P1）

```powershell
python tools/charextract/prepare_facial_controller.py --manifest manifest --out work\preview\preview\assets
```

读 `manifest/facial-controller-config/FacialSubModelConfig_NPC_<npc>.json`，输出 `<角色>/facial/controller.json`。
脚本会核对映射表里的 pose 是否存在于 `<角色>/animation/poses.json`，把缺失项写进 `stats.missingPoses`
（00401 / 01101 = 0，06201 = 113，因其无 PoseAsset），不静默丢弃。

`controllerConfig` 的 key 数等于不带 `_Neg` 的正曲线数；负方向由 `attributes` 里 `weight=-1` 的
`_Neg` pose 表达。前端只采样正曲线，按 `v(t)×A.weight` 求贡献，正值才施加到对应 pose（`addPose` 只接受
非负权重），再按 pose 聚合叠加。`jawOpen` / `blinkScale` 只统计、不施加。

## 5. 构建前端

```powershell
cd preview
npm install
node build.mjs
```

产出 `preview/app.bundle.js`（esbuild 打包 three.js + 预览代码）。

## 6. 打包成单文件

```powershell
python tools/charextract/pack_multi.py --data work\preview --code preview
```

产出 `work\preview\原版人物渲染预览.html`：所有模型、贴图、动作以 gzip + base64 内联进一个 HTML，`networkRequired = false`。

## 7. 验证

浏览器打开成品，右上角切角色、切动作、调材质。控制台应当 **0 error**。

**表情验证**：选一个带口型的动作（例如「对话动作 · World_Dialogue_1」），切到「脸部」视图，把「播放进度」拖到中间位置。嘴应当开合。右侧「原版变形目标表情（眉 / 眼睑 / 嘴）」开关可做同帧 A/B——关掉后嘴会立刻闭合成一条细线。

**注视验证**：伊里斯 + 带 4 通道曲线的动作（如 `Fight_CallOut`），「瞳孔材质控制」里的「原版注视曲线（跟随动作）」开关做同帧对照；关掉后瞳孔回到中性位置。它与「演示扫视」互斥，`NPC_00401` 会提示无数据。

**多通道面部验证（P1）**：参考角色 `NPC_00401` → 表情片段「原曲线全通道 · controllerConfig」→「脸部」视图 → 进度拖到 2 s，与「跟随身体动作」同帧对照。108/108 pose 可用；路易斯仅 20 个 pose 有非空增量，伊里斯没有该选项（无 PoseAsset）。

脚本化校验：

```powershell
python tools/charextract/pack_multi.py --data work\preview --code preview
# 读 preview-build.json 拿到 sha256 与体积
```

精灵着色器的指令级对拍是独立于成品 HTML 的自包含页面：

```
preview/pet-validate.html          # 整帧对拍，期望 RESULT: PASSED
preview/pet-probe2.html?key=body  # 逐指令二分定位
```

它们自带 GLSL、只 fetch `pet/*.json`，不依赖 `materials.js` / `app.js`，所以可以脱离整条管线单独跑。

## 目录约定

```
work/                     你的工作目录（不入库）
├── npc00401/ npc01101/ npc06201/    每个角色一份提取结果
│   └── animation-research/          morph-poses/ 与 native-animation/
│                                    （prepare_morph.py 的输入）
├── materials/                       材质解析结果 + shaders/
└── preview/                         装配产物 + 打包输出
    └── preview/assets/<角色>/morph/ 变形目标与口型曲线
    │                            （prepare_morph.py 的输出）
    └── preview/assets/<角色>/gaze/  原版眼睛注视曲线
    │                            （prepare_eye_gaze.py 的输出）
    └── preview/assets/<角色>/facial/ 原版 controllerConfig 映射
                                     （prepare_facial_controller.py 的输出）
```

`manifest/characters.manifest.json` 决定装配哪些角色、用哪套材质：

```json
{
  "characters": [
    { "id": "npc06201", "dir": "npc06201", "label": "伊里斯 NPC_06201",
      "npc": "NPC_06201", "kernel": "npc",
      "materials": { "body": "MI_NPC_06201", "im": "MI_NPC_06201_Im",
                     "face": "MI_NPC_06201_Fe", "eyes": "MI_NPC_06201_Es",
                     "outline": "MI_NPC_06201_Outline",
                     "faceOutline": "MI_NPC_Fe_03_Outline" } }
  ]
}
```

`kernel` 决定用哪套材质语义：人形 `npc`，精灵 `pet`（PetBase 材质族，参数名与常量缓冲结构都不同）。
