# 材质与着色器还原

## 材质链怎么读出来的

每个材质实例（`MaterialInstanceConstant`）本身只存"覆盖值"，真正的绘制逻辑在父材质图（`M_C_Face` / `M_C_Object`）里。所以流程是：

1. 定位保存资源 → 材质实例 → 材质图；
2. 沿父材质链逐级回溯，求出每个参数的**有效值**（实例覆盖优先，没有就继承，再没有就取图级默认）；
3. 记录贴图绑定（`ObjectPath` 指向哪张贴图）与常量缓冲（来自该材质引用的 BasePass 程序）。

所有这些都落在 `materials.json`：

```
instances[kind] = { name, chain, scalar, vector, texture }
buffers[kind]   = { ...64 行 float4..., source: "<shader>-evaluated.json" }
defs[kind]      = { uBase, uMask, uId, uFace, uMatcap, uHue, uRamp }
```

`buffers` 里的常量缓冲不是猜的，是从着色器程序求值出来的 `evaluated` JSON。

### 缺省纹理怎么办

有些材质实例没有自己的贴图覆盖（比如脸部材质缺 MaskTex）。这时候沿父链回退到**图级默认纹理**，并且把回退结果如实记进 `instances[kind].graphDefaultTextures`，不静默丢弃也不伪造。

已知的图级默认：

| 材质图 | 参数 → 默认贴图 |
|---|---|
| `M_C_Face` | MaskTex→TestResMaskTex、MatID→TestResIDTex、BaseTex→TestResMainTex01、RampTex→TestResMainTex01、FaceTex→TestResMaskTex01 |
| `M_C_Object` | MainTex→Tex_PetGlassy_007_D、MaskTex→TestResMaskTex、StarStickTex→Tex_PetGlassyStar_004、MatID→TestResIDTex、MatCap→TestResMainTex01、GlassyMask→TestResGrayTex、BaseTex/RampTex→TestResMainTex01 |

## 像素着色器

原版用的是 DXBC（DirectX bytecode）。做法是**机械转译**，不是照着画面反推公式：

- `tools/charextract/dxbc_interp.py` —— DXBC 指令解释器，把着色器当成可执行程序跑；
- `tools/charextract/dxbc_glsl.py` —— 同一个解释器的 GLSL 后端，输出 GLSL；
- `tools/charextract/pet_kernel.py` —— 同一套语义的 numpy kernel，用来交叉验证；
- `tools/charextract/pet_runtime.py` —— 运行时常量状态（cb0..cb6）装配。

所以 GLSL 和原程序**同源**，正确性不靠肉眼比画面，而是靠逐指令对拍。

### 对拍结果

`preview/pet-validate.html` 是一个自包含的验证台（自带 GLSL，fetch `pet/*.json`），不依赖 `materials.js` / `app.js`。

**逐指令对拍**（每个程序跑到全 PASS）：

| 程序 | 指令数 | 探针覆盖 |
|---|---|---|
| body | 181 / 181 | PASS |
| body1 | 165 | PASS |
| eyes | 178 | PASS |
| outline | 104 | PASS |

每个探针取 8 组样本 × r0–r3 全寄存器**逐分量**比对，容差 ≤ 1e-4。

**整帧对拍**（`?mode=nodiscard`，120 样本/程序）：

| 程序 | maxAbs |
|---|---|
| body | 1.120e-7 |
| body1 | 1.143e-7 |
| outline | 2.451e-9 |
| eyes | 0 |

`RESULT: PASSED`，texture sanity `[0.25, 0.5, 0.75, 1]` `glError=0`。

numpy kernel 对原程序的偏差：**2.22e-16**。

### 一个已知的坑

本机 ANGLE 对 `mix(x, y, floatVec)` 和布尔向量复合会错误编译，所以转译器把 `mix` 展开成显式算术选择。这个改动只影响精灵着色器；人形走的是另一套 kernel。

## 顶点着色器

人形用标准蒙皮 VS + 描边膨胀。精灵的 outline **顶点膨胀段尚未移植**（原 VS 指令 ~140–213 的膨胀区段），但精灵的 outline **像素着色器已精确移植并通过逐指令对拍**——两者是独立的，PS 对拍通过不意味着 VS 膨胀已还原。

## 预览侧的运行时标量

原程序从常量缓冲读很多运行态值（灯光向量、环境色、ramp 宽度与对比度、阴影偏移、ramp 混合……），这些在烘焙资源里是 0，真实值由游戏运行时填。

预览用的是**人工选定的工作室光照**，用于检查材质本身，不等于原游戏画面。相关说明见 [05-未完成与限制.md](05-未完成与限制.md)。
