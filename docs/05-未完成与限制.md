# 未完成与限制

这份文档只写**没做到**的部分。做到的部分见 [01](01-角色数据事实.md) / [02](02-材质与着色器还原.md) / [03](03-动画还原.md)。

原则：**不伪造、不静默丢弃、不用"看起来差不多"的东西顶替**。下面每一条都是实打实没解决的。

## 1. 无 PoseAsset 角色的骨/轴满权重增量没有拿到

**状态：混合语义已经查清，规则也验证过；缺的是数值。**

原版的脸由两套机制叠加：变形目标（blend shape）负责主要形变，骨骼通道负责修饰。
后者以前只留档没施加，是因为不知道该怎么施加 —— 现在查清了：

```
曲线名 C → FacialSubModelConfig_NPC_<npc>.controllerConfig[C]
        = { auGroup, auGroupNeg, attributes:[{pose, weight, jawOpen, blinkScale}] }

对每个属性 A：贡献 = v(t) × A.weight，施加到 pose = A.pose 的骨骼增量
```

`pose` 名与 PoseAsset 的 pose 同名，`auGroup` 是标准表情动作名。映射表在
`NRC/Content/NewRoco/DataConfig/FacialConfig/`（**不在角色目录下**，这是之前一直没找到的原因）。

三个角色的情况：

| 角色 | PoseAsset | 曲线→pose 命中 | 现状 |
|---|---|---|---|
| NPC_00401 | 完整（108 个非空 pose，13 根骨） | 108 / 108 | **可完全施加**，规则已被 24 个通道独立交叉验证（比值中位数 0.992） |
| NPC_06201 | 无 | 113 / 113 | 映射表与 AU 归属已知，**缺每个骨/轴通道的满权重增量** |
| NPC_01101 | 有但几乎空（176 个 pose 只有 20 个非空，只涉及 4 根骨） | 175 / 175 | 映射表与 AU 归属已知，**缺 12 根骨的增量** |

**缺的那个数字在哪、为什么读不出**：

- 客户端**没有**通用脸模资产（全量包索引检索 `zuiba` / `FaceModel` / `FaceRig` / `AUFace` / `Viseme` 全部 0 命中）；
- `/Script/FacialAction` 是**编译态 C++ 模块**，`FacialSubModelConfig` 与 `FacialWeight` 的类都来自它，常量读不出；
- `ABP_SKM_NPC_06201_Skin.uasset` 的图是字节码（`ExecuteUbergraph_…` / `AnimGraph` 两个 UFunction，属性数为 0）；
- 伊里斯的**所有**原版 clip 都不含她那 13 根脸骨的轨道，**没有可对拍的烘焙结果**。

**影响**：伊里斯与路易斯的脸能靠变形目标动（这部分已经实现并验证），但原版那套「曲线直接驱骨骼」的修饰层还没接上。

**顺带查到的原版眼睛注视数据**（还没接进预览）：每个 clip 自带 `ec_u_offset_l/r`、`ec_v_offset_l/r`
（眼睛材质 UV 偏移，材质函数 `MF_FacialAnimationUV`）。伊里斯 94 个 clip 带这个数据，
u ∈ [-0.0835, 0.0646]、v ∈ [-0.3215, 0.1108]。预览现在的「演示扫视」是人工正弦波，可以换成原版数据。

## 2. 伊里斯没有 PoseAsset

`PA_NPC_06201_Skin.uasset` 导出后全是 `UPhysicsAsset` / `USkeletalBodySetup` —— 它是 PhysicsAsset。

所以她的附加姿势集是**空的**。这是如实记录，没有借用其他角色的姿势来凑数。`NrcChar` 对 `PA_` 前缀做了过滤并打印诊断信息，就是为了把这种情况和"真没有姿势"区分开。

## 3. 精灵的 outline 顶点膨胀未移植

精灵的 outline **像素着色器**已精确移植并通过逐指令对拍（104/104 指令 PASS）。

但**顶点着色器里的膨胀区段**还没搬。原 VS 在指令 ~140–213 做沿法线的顶点膨胀，关键量涉及 `cb3[24].x/.y`、`cb1[45..48]`、`cb1[23]`、`cb3[12..15]` / `cb1[153].z`，以及指令 175 `mad r2.yz, r6.xxyx, r2.yyzy, r3.xxyx`。

原 VS 在 `_nrc_work/petmats/shaders/shader-5f17f79efc56b7ae540fa4a0ce9b7529efc1e960.asm`（237 条可执行指令，含完整蒙皮）。

**影响**：精灵的描边宽度/位置在预览里不完全等于原版。

> 精灵形态目前**不在交付的预览 HTML 里**——它已按要求从成品中移除。相关工具链与对拍台仍保留在仓库的 `tools/charextract/pet_*.py` 和 `preview/pet-*` 里。

## 4. 预览的运行时标量是人工选定的

原程序从常量缓冲读大量运行态值：灯光向量、环境色、ramp 宽度与对比度、阴影偏移、ramp 混合、`cb6[32..37]` 等。这些在烘焙资源里是 0，真实值由游戏运行时按天气、场景 CLV、时段填。

预览用的是**一套工作室光照**（方向 -35°/38°、主光 1.0、环境 0.65、阴影 0.65），用来检查材质逻辑是否正确，**不等于原游戏画面**。

**具体没做**：

- 未接入原游戏 CLV / 天气 / 完整调色；
- 未恢复原始 `.ush` 正文；
- 未复现完整状态机、过渡混合；
- 未复现程序化注视与弹簧骨骼。

## 5. 角色的"附加骨骼姿势"不是原版全部表情

预览里的 109 / 176 个姿势来自原版 PoseAsset，可以直接叠加。

原版游戏里还有**表情片段（Face_Expression）、注视（Pos_Look*）**等更细的混合逻辑，目前是作为独立选项列出，而不是按原版的方式互相混合。

口型片段（`KouXing_*`）已经能用了——这些 clip 自带的曲线名字命中真实变形目标，所以选中即生效；但它们与表情片段、PoseAsset 姿势之间的**相互混合顺序与权重规则**仍未还原。

## 6. 精灵形态没有纳入成品

按要求，精灵形态（`SKM_Lig_YiLiSi3_001`）已从交付 HTML 中**彻底移除**：代码路径、manifest 条目、资产目录全部清理，打包后的 243 个文件里没有任何精灵资源或精灵着色器。

工具链成果保留（转译器、numpy kernel、对拍台），作为后续继续做精灵的起点。

## 7. 其他边角

- 贴图解码依赖 AssetRipper 纹理解码器路径；对该游戏之外的 UE 项目不一定适用。
- `CUE4Parse_src` 里 `CUE4Parse-Natives/ACL/external/acl` 是 submodule，原生库由轻量包的 DLL 承载，仓库里没有编译它。
- `tools/charextract/_one_shot_patches/` 里两个 `patch_*.py` 是历史一次性补丁脚本（硬编码绝对路径），**它们的改动已经并入 `prepare_multi.py`**，保留只为溯源，不参与任何构建。
